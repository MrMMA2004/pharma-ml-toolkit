16. COMPLETE GUI REDESIGN USING PYSIDE6, PYQTGRAPH, QT-MATERIAL, AND
QDARKSTYLESHEET

16.1. Primary Objective

Completely redesign the existing application's graphical user interface using four
complementary technologies:

1. PySide6 (Qt for Python): The primary desktop GUI framework.
2. PyQtGraph: The scientific plotting, data visualization, and interactive graphics engine.
3. Qt-Material: The primary UI styling and Material Design theme system.
4. QDarkStyleSheet: An optional alternative dark/light styling framework.

Official repositories:

- PySide6: https://github.com/qtproject/pyside-pyside-setup
- PyQtGraph: https://github.com/pyqtgraph/pyqtgraph
- Qt-Material: https://github.com/UN-GCPDS/qt-material
- QDarkStyleSheet: https://github.com/ColinDuquesnoy/QDarkStyleSheet

The objective is to transform the existing GUI into a professional, modern, intuitive, responsive,
visually consistent, and maintainable desktop application.

This is a complete UI/UX redesign, not merely a cosmetic modification.

Preserve all existing backend functionality, database integrations, algorithms, modules,
datasets, and application capabilities while replacing or substantially improving the graphical

presentation and user interaction layer.

The redesigned interface must provide appropriate visual and interactive access to all relevant
project features, including scientific data, computational workflows, database operations, and
machine learning functionality.

16.3. Framework Responsibilities and Integration Strategy

Use each library according to its intended purpose.

Technology| Responsibility| Implementation Strategy
PySide6| Application architecture| Main windows, navigation, forms, dialogs, widgets, events
PyQtGraph| Data visualization| Scientific charts, image analysis, interactive plots, data
exploration
Qt-Material| Primary styling| Material Design, colors, typography, themes, visual consistency
QDarkStyleSheet| Alternative styling| Optional dark/light themes and palette customization

Architecture Rules

- PySide6 must be the primary GUI framework.
- PyQtGraph must provide scientific and computational visualizations.
- Qt-Material should be evaluated as the default styling system.
- QDarkStyleSheet should be treated as an alternative styling provider rather than automatically
combined with Qt-Material.
- Avoid conflicting global stylesheets.
- Create a consistent styling interface so that the application can switch between supported
theme providers without rewriting individual screens.
- Do not mix PyQt and PySide bindings in the same application process.
- Use native PySide6 widgets wherever possible.
- Use custom widgets only when they provide a genuine improvement.

The application architecture must remain modular and maintainable.

16.5. GUI Architecture

Implement a clean separation between three primary layers:

1. Presentation Layer

PySide6 windows, widgets, dialogs, navigation, styling, and visualization components.

2. Application Logic Layer

Existing business logic, algorithms, computational workflows, model execution, and application
services.

3. Data Layer

Database operations, data access, data models, persistence mechanisms, and external data
sources.

Use an appropriate architecture such as MVC, MVP, or MVVM when justified by project
complexity.

Requirements:

- Keep GUI code separate from business logic.
- Avoid placing database queries and computational algorithms directly inside widget classes.
- Reuse existing backend functions and modules.
- Use Qt signals and slots for component communication.
- Keep UI components modular and reusable.
- Ensure that GUI components do not depend unnecessarily on database implementation details.
- Allow the GUI to evolve independently of the backend.
- Avoid unnecessary architectural complexity.

16.10.2. Optional Alternative Theme Provider

Implement QDarkStyleSheet only if its verified compatibility and visual behavior justify including

- Qt-Material themes.
- QDarkStyleSheet themes.
- Native Qt styling, if useful as a fallback.

16.10.3. Qt6 Compatibility Verification

Before adopting QDarkStyleSheet:

- Inspect its latest release and official compatibility information.
- Verify PySide6 compatibility using the installed version.
- Check its Qt6-related limitations and known instabilities.
- Test all essential widgets.
- Check its behavior with PyQtGraph.
- Pin a verified dependency version.
- Document any remaining limitations.

Do not assume that compatibility with older Qt versions automatically guarantees reliable
behavior with the current PySide6 environment.

16.10.4. Styling Conflict Prevention

Never apply Qt-Material and QDarkStyleSheet globally as competing stylesheets.

Use one active global theme provider at a time.

When switching providers:

1. Remove or replace the previously active stylesheet.
2. Apply the selected theme.
3. Refresh relevant custom components.
4. Update visualization colors where necessary.
5. Verify that the interface remains visually consistent.

16.14. Responsiveness and Background Processing

The graphical interface must remain responsive during computationally expensive operations.

- Never execute long-running calculations directly on the GUI thread.
- Use "QThread", "QThreadPool", "QRunnable", or another appropriate background execution
mechanism.
- Provide progress indicators for long-running operations.
- Support cancellation where technically safe.
- Handle worker errors and communicate results through Qt signals.
- Prevent duplicate submissions of expensive operations when necessary.
- Avoid race conditions and unsafe shared-state access.
- Release resources appropriately when background tasks finish.
- Avoid updating GUI widgets directly from worker threads.

Pay particular attention to:

- Database operations.
- Machine learning workflows.
- Model training.
- Data processing.
- Large file operations.
- Scientific visualization preparation.
- Dataset loading and preprocessing.

For live plotting, use efficient update mechanisms and avoid repeatedly rebuilding entire plots.

1. Audit the existing GUI and its backend dependencies.
2. Document existing user workflows and GUI capabilities.
3. Establish the new PySide6 architecture.
4. Inspect and evaluate all three complementary libraries: PyQtGraph, Qt-Material, and
QDarkStyleSheet.

5. Verify package and environment compatibility.
6. Establish the new design system and theme strategy.
7. Design the main application structure and navigation.
8. Implement the main window and reusable components.
9. Implement the centralized theme manager.
10. Integrate scientific visualization components.
11. Migrate existing features incrementally.
12. Connect each interface component to the appropriate backend functionality.
13. Validate each completed screen.
14. Perform integration and regression testing.
15. Remove obsolete GUI components only after their replacements have been verified.

Maintain recovery points and preserve working versions throughout the migration.
