# MIGRATION_WINUI3 — the part10 campaign ledger

**Master prompt**: "Complete Migration to C# WinUI 3 + XAML + MVVM,
Full Python Backend Integration via FastAPI and WebSocket,
Nine-Workspace GUI Reconstruction, PySide6 Retirement, and Fully
Self-Contained Offline Windows EXE Installer."

This is the Phase-One audit + the campaign's honest ledger. Every
claim below is live-verified against the working tree; the BLOCKED
markers are exactly that — the campaign's own non-negotiables forbid
claiming Windows-host work from a Linux container.

---

## 0. The environment boundary (read this first)

The development container is **Linux-only**. Consequences, stated
once and referenced everywhere below:

| part10 deliverable | Linux-container status |
|---|---|
| C# WinUI 3 / XAML / MVVM frontend **build & execution** | **BLOCKED** — WinUI 3 + Windows App SDK compile and run on Windows 10/11 only; no Windows host exists here. |
| FastAPI backend integration layer (Phase Six) | **REAL** — fully implemented and tested here. |
| Backend process lifecycle + startup handshake (Phase Seven) | **REAL** (backend side) — port-0 loopback bind, structured handshake, graceful shutdown, all tested. The *WinUI-side* supervisor (job objects, restart policy) is BLOCKED with the frontend. |
| Background Job Architecture (Phase Nine) | **REAL** — state machine, cooperative cancellation, progress events, tested. |
| PySide6 retirement (Phase Sixteen) | **BLOCKED** — the prompt's own rule #9: retire only after the new GUI passes complete functionality-parity; the new GUI cannot be built or tested here. PySide6 **stays** production. |
| Offline Windows EXE installer (Phases Eighteen-Twenty) | **BLOCKED** — same boundary as part9's §14 (a Windows host; see `packaging/windows/BUILD_REPORT.md`). |

Nothing on this page weakens a non-negotiable: no "scaffolded as
done", no cosmetic screenshot passed off as parity.
