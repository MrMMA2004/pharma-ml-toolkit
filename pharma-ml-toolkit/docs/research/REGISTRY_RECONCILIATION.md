## 2. Consistency findings

1. **`nlmixr2/rxode2` status disagreement.** The Link Registry records it as
   absorbed (v1.2.102 PK/PD round, register #19); the catalog labels it
   "supplemental" while listing the superseded archived
   `nlmixrdevelopment/RxODE` as in-conversation. The catalog audit resolves
   the practical question (row 78: "GUI linked" — exact linCmt
   compartments/events drive the regimen pane), but the canonical index must
   carry the registry's absorption status, not the catalog's label.
2. **Org renames.** `selfies` (aspuru-guzik-group → the-matter-lab) is the one
   rename between the two registries; the catalog audit additionally records
   live redirects (`awesome-molecular-docking`, `ydata-profiling`,
   `AutoDock-Vina/GPU` → forlilab). A canonical index should store both the
   given slug and the resolved slug.
3. **The catalog is not a superset.** Six absorbed lineages + the backup repo
   are absent (§1). Any future "complete repository index" must merge both
   sources; neither is complete alone.
4. **The two registries describe different things.** The Link Registry is a
   *provenance* record (which instruction introduced which repository, when,
   into which module); the catalog audit is a *disposition* record (what the
   toolkit actually implements per repository, with live evidence). Both
   dimensions are worth keeping — as columns, not as separate documents.

## 3. Recommendation: one canonical machine-readable index

Create `docs/research/repository_index.json` (schema sketch):

```json
{
  "slug_given": "the-matter-lab/selfies",
  "slug_resolved": "the-matter-lab/selfies",
  "aliases": ["aspuru-guzik-group/selfies"],
  "source": {"link_registry": 5, "catalog_section": 5, "catalog_label": "conversation"},
  "introduced": {"version": "v1.2.97", "date": "2026-10-29"},
  "disposition": {"status": "covered", "evidence": "chem/selfies_codec.py ..."},
  "archived_upstream": false
}
```

Seeded from: the 34 registry entries (including the 6 absent from the catalog
and the backup repo) + the 140 catalog-audit rows. Generated by script (like
`tools/build_docs_index.py`), not hand-maintained. The per-repo
*disposition* column defers to `GITHUB_RESEARCH_CATALOG_AUDIT.md` as the
single authority — this index adds the provenance dimension and the alias map.
