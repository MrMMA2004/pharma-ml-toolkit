# PharmaML Studio — Windows installer packaging (MASTER_PROMPT part9)

This directory is the complete, reproducible Windows-deployment pipeline for
PharmaML Studio: **PyInstaller "onedir" + Inno Setup**, per the part9 §2
evaluation (onedir keeps the scientific bundle inspectable and startup fast;
§2 explicitly forbids trading reliability for a one-file executable).

## One-command build (on a Windows 10/11 x64 machine)

```bat
pharma-ml-toolkit\packaging\windows\build_windows.bat
```

Prerequisites on the build machine (nothing else):

1. **Python 3.12 x64** on PATH (the pinned stack's QA family),
2. **Inno Setup 6** (default install path is auto-detected, or set
   `INNO_SETUP` to `ISCC.exe`).

The script creates its own clean venv (§10), installs the torch CPU wheel
from PyTorch's CPU index, then the pinned stack, runs the full pytest gate,
freezes the app, validates the dist, compiles the installer, and writes
`release/windows/{PharmaML_Studio_Setup_vX.Y.Z.exe, SHA256SUMS.txt,
RELEASE_MANIFEST.json, BUILD_REPORT.md}`.

## Clean-machine testing (§14 — MANDATORY before any "standalone" claim)

Test in Windows Sandbox / a clean VM **without** Python, Anaconda, pip
packages, or the developer's PATH: install from the Setup EXE fully offline,
launch from Start Menu and Desktop, then run the §14.2 representative
scientific flows (CSV/Excel import, descriptors, fingerprints, a small ML
train, a prediction, a plot + figure export, model save/reload, a docking
run with the bundled engines) and the §14.3 offline checks. The
§14.1/§14.2/§14.3/§14.4 checklists in `BUILD_REPORT.md` are the recording
sheet — a capability is only "verified" when exercised, not when its page
opens.

## The honest status of THIS repository (2026-11-17, round 272)

The packaging infrastructure, audits and validation above are real and
committed. **The actual installer EXE is NOT built by this repository's
Linux sandbox** — PyInstaller cannot cross-compile Windows binaries from
Linux, no Windows host or Wine is available here, and the full Windows
scientific stack (torch-CPU, PySide6, catboost) would exceed the sandbox's
disk. This is recorded as **BLOCKED** in `BUILD_REPORT.md` with the exact
limitation, per part9's own status vocabulary — never as PASS.

To produce the real installer: run `build_windows.bat` on any Windows
10/11 x64 machine with Python 3.12 + Inno Setup 6, then perform the §14
clean-machine protocol. Everything else in this directory is done.

## Key packaging decisions (the audit trail)

* **Frozen resource layout** — the app's own `__file__`-relative resource
  math is preserved: `ui/font_loader.py` finds `fonts/` at the bundle root
  (`_internal/fonts`), and `pharmaml/docking/workflow.py`'s engine discovery
  finds the AutoDock trio at `_internal/pharmaml/engines` (SHA-256 and
  PE-machine validated by the app's OWN contract — the installer cannot
  ship a corrupted engine silently).
* **multiprocessing (§13, inspected before acting)** — the only spawn pool
  lives in `docking/ligands.py`, launched from worker threads with plain
  picklable tuples; the GUI is behind the `__main__` guard in `studio.py`,
  which now calls `multiprocessing.freeze_support()` on Windows (a no-op
  in every unfrozen session, verified by the test suites).
* **VC++ runtime (§6)** — PyInstaller bundles `VCRUNTIME140.dll` (and the
  MSVCP/VC runtime DLLs the wheels carry) **app-local** into the dist, so
  no separate vc_redist install is required; the clean-machine test is the
  proof that settles it.
* **Offline (§8)** — the app has ZERO network imports (AST-audited); no
  credentials ride in the bundle (`packaging_validation.py` scans for
  token/key material and fails the build on a hit).
* **Size (§12)** — no dev/test packages (pytest/mypy/ruff excluded),
  UPX and strip are DISABLED for Qt/scientific DLLs (§12 forbids blind
  stripping), the torch wheel is the CPU build; the top-20 size report is
  printed by validation so the largest components are always visible.

## External executables (§5)

`vina.exe` (x64), `autogrid4.exe`/`autodock4.exe` (x86) ship in `engines/`
and are bundled (the app validates their SHA-256 + PE machine itself).
GROMACS is not used anywhere. Open Babel is an optional, guarded
capability (MOL2 export) that reports its own absence clearly in the GUI
result rows when the user has not installed it — deliberately not bundled
(GPL wrapper + native library); see `DEPENDENCY_INVENTORY.md`'s §5 note.
