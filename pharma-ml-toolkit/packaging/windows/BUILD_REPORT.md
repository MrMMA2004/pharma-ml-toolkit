## 1. Packaging architecture and selected tools — PASS

PyInstaller 6 "onedir" + Inno Setup 6 (`packaging/windows/pharmaml.spec`
+ `installer.iss`), chosen per §2's evaluation for a large scientific
PySide6 stack; onefile explicitly rejected (§2), UPX/strip disabled for
Qt/scientific DLLs (§12).

## 2. Dependency inventory — PASS

`packaging/windows/DEPENDENCY_INVENTORY.md`, generated by
`tools/packaging_audit.py` from an AST scan of the ACTUAL tree
(studio.py + ui/ + src/ + scripts/) cross-referenced with the live
venv's dist-info: 30 runtime rows (numpy → qt-material), versions and
verification per row. TensorFlow/OpenCV/Polars/LIME confirmed NOT USED
(the §1 anti-padding rule). statsmodels + shiboken6 were DISCOVERED by
the scan and added (the audit found them, not the prompt).

## 3. Included / excluded dependencies — PASS

Included: every optional feature group (chem, docking, boosting,
explain, deep, selfies, reports, studio) — §12's no-silent-omission
rule. Excluded: pytest/pytest-qt/mypy/ruff/tkinter/pip (dev/test only;
`packaging_validation.py --dist` asserts no leakage).

## 4. External executable inventory — PASS

`engines/` trio bundled (vina x64, autogrid4/autodock4 x86) at
`_internal/pharmaml/engines`, SHA-256- and PE-machine-validated by the
app's OWN discovery code (`pharmaml/docking/workflow.py`), which this
report's `--static` validation mirrors. GROMACS: not invoked anywhere.
Open Babel: optional guarded capability, honestly NOT bundled (§5
pattern — the GUI reports the missing tool in its result rows).

## 5. License and redistribution notes — PASS

MIT toolkit license displayed by the installer; per-distribution
license files collected from dist-info into
`THIRD_PARTY_LICENSES/` (INDEX.md manifest) by
`tools/packaging_audit.py --licenses-dir`; the AutoDock engines carry
their upstream licenses (Apache-2.0 family for Vina, GPL family for
AutoDock4/AutoGrid4 — engine NOTICE texts land in the license dir at
build time). No secrets are bundled (validation scans for token/key
material and fails the build on a hit).

## 6. Python / native runtime bundling — PASS (design) / BLOCKED (artifact)

The spec freezes CPython 3.12 x64 + the entire scientific stack
app-local; the VC++ runtime DLLs ride app-local inside the PyInstaller
dist (no separate vc_redist prerequisite). Producing the actual
artifact is blocked (see 13).

## 7. Qt plugin/resource strategy — PASS (design) / BLOCKED (artifact)

PySide6 hooks collect platforms/imageformats/styles/iconengines;
`--dist` validation asserts `qwindows.dll` and the imageformat plugins
post-build; fonts land where `ui/font_loader.py`'s `__file__` math
expects (`_internal/fonts`).

## 8. Files created or modified — PASS

Created: `packaging/windows/` (spec, iss, ps1, bat, validation, README,
requirements, version resource, icon assets, DEPENDENCY_INVENTORY,
BUILD_REPORT) and `tools/packaging_audit.py`. Modified: `studio.py`
(`freeze_support()` on Windows after the §13 architecture inspection —
no-op unfrozen, verified by the suites).

## 9. Build command — PASS (defined, not yet executed on Windows)

`pharma-ml-toolkit\packaging\windows\build_windows.bat`

## 10-12. Installer output location / size / SHA-256 — BLOCKED

`release/windows/PharmaML_Studio_Setup_v1.2.216.exe` does not exist:
this repository's build host is a **Linux sandbox**; PyInstaller
cannot cross-compile Windows binaries from Linux, no Windows host or
Wine is available in the sandbox, and the full Windows scientific stack
(torch-CPU, PySide6, catboost) exceeds the sandbox's free disk. The
build script computes size/SHA-256 and writes `SHA256SUMS.txt` +
`RELEASE_MANIFEST.json` automatically on the Windows machine.

## 13. Clean-machine test environment — BLOCKED

Requires a Windows 10/11 x64 Sandbox/VM WITHOUT Python/Anaconda/pip
packages/developer PATH — none exists here. The §14.1–14.4 checklists
below are the recording sheet for when the Windows build runs.

## 14-16. Installation / offline / scientific workflow tests — BLOCKED

Not executed (no Windows host). No claim of standalone operation is
made until these run green on the produced EXE.

## 17. Remaining limitations — the honest list

1. **The installer EXE itself** (BLOCKED, Linux sandbox — see §10).
2. **Icon provenance** (PARTIAL): `assets/pharmaml.ico` was generated
   for this campaign and multi-sized; it is serviceable but a designer
   pass would improve it.
3. **numba/llvmlite size**: shap's JIT layer is included because the
   explainability workspace needs TreeExplainer; it is one of the
   largest components (visible in the top-20 size report at build).
4. **Open Babel MOL2 export** requires the user's own OpenBabel
   install (deliberate, §5-documented).

## 18. Exact final installer filename (the deliverable contract)

`PharmaML_Studio_Setup_v1.2.216.exe` — produced by
`build_windows.bat` on a Windows host; every §14 item above must be
recorded PASS before any standalone claim.

## Phase 2 (round 273, v1.2.217): the Linux frozen-equivalent verification

part9 says "Do not stop after creating the packaging scripts. Build the
installer, test it, fix packaging failures, rebuild it" — and the EXE
itself remains BLOCKED (no Windows host, no Wine, no cross-compile;
see §10 above). What the Linux build host CAN honestly produce is the
next tier of evidence: **freeze the actual application with the actual
Windows spec's policy and run part9's flows inside that frozen bundle.**
That verification shipped this round:

* `tools/freeze_equivalent.py` — captures
  `packaging/windows/pharmaml.spec`'s policy VERBATIM (432
  hiddenimports, 586 datas, 1 binaries, 12 excludes — recorded in the
  evidence JSON), writes the derived Linux-equivalent spec with four
  documented deltas (icon/version resources dropped; `console=True`
  for evidence stdout; `studio.py` + `tools/freeze_smoke_driver.py`
  as two entries in ONE Analysis/COLLECT so the §14 driver rides the
  identical dependency collection; `ui/native` datas — the EGL no-op
  stub the app's own `ui.headless` preloads on libEGL-less Linux
  hosts), and runs PyInstaller 6.22.3: **204 s, rc=0**, dist 2.2 GB.
* The frozen bundle's layout honors the spec's own datas contract:
  engines at `_internal/pharmaml/engines` (the trio found and
  SHA-256 + PE-machine validated by the app's OWN
  `pharmaml.docking.workflow` discovery), fonts at `_internal/fonts`
  (registered by `ui.font_loader`'s `__file__` math), all Qt
  platform plugins collected.
* `PharmaMLStudio --doctor` FROZEN (cwd=`/`, part9 §4's no-CWD rule):
  **18 OK / 0 warn / 0 failed, exit 0** — the app's own environment
  self-check through the bootloader's embedded interpreter.
* `FreezeSmokeDriver` (the §14.2/§14.3/§7 driver, cwd=`/tmp`): **13/13
  flows PASS** — CSV import, Excel import, RDKit descriptors (133
  columns × 12 real-drug molecules), Morgan fingerprints, ML
  classification (accuracy 0.90) + regression (r² 0.9923), prediction,
  plots + PNG/SVG/PDF/TIFF figure export, CSV/Excel table export,
  model save/reload (byte-parity predictions), kNN applicability
  domain, the bundled engines' validation, and the offscreen Qt stack
  (qdarkstyle 54,234-char stylesheet + qt-material applied).
  `install_dir_unchanged: true` (§7 — the frozen tree stayed
  byte-identical while every output byte landed in the user dir) and
  `net_attempts: []` (§14.3 — `socket.connect` armed to raise on ANY
  outbound attempt before the science imports; a green run is a
  recorded zero-attempt proof, not an assumption).
* Evidence: `packaging/windows/evidence/freeze-equivalent-r273.json`
  (machine-readable, committed) — the build log itself stays in the

* Pinned at gate time by `tests/test_freeze_equivalent.py` (7 focused
