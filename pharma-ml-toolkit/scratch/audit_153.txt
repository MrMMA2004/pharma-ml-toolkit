[F1] RED — playground.py ~16958-16983, _ml_plot_correlation_heatmap:
     the target-column join is SWAP-DISHONEST. The handler joins the
     target from the SESSION frame (session_frame.loc[frame.index,
     target]) instead of the run's own y_test. The comment claims "a
     swapped dataset makes the join dishonest, so it is skipped, not
     faked" — the guard only catches index NON-coverage. probe g2
     (natural flow: train on A, adopt same-shaped B with RangeIndex,
     click the button) proves the pairing: the a-y cell read +0.17
     (B's noise y against A's features) where the run's own y_test
     (y = 10*a) gives +1.00. The run tuple ALREADY carries the honest
     y_test (aligned with x_test by construction) — the session-frame
     route has no advantage and one silent-dishonesty failure mode.
     FIX: join the target from the run's own y_test; keep a tolerant
     fallback only for a non-Series y_test; regression-test the swap.

[F2] AMBER — features.py:1579, filter_low_variance's threshold guard:
     `threshold = float(threshold)` coerces BEFORE validation, so
     True -> 1.0 and '0.01' -> 0.01 are ACCEPTED (probe D2). The house
     guard family rejects bools/strings at the door (interpret.py's
     radius/bit, viz top_n: "top_n must be a positive integer or None,
     got '5'"). FIX: reject bool and non-real types before the coercion.

[F3] AMBER — features.py:1613-1618, filter_low_variance keeps
     inf-poisoned columns SILENTLY: fillna(0).var() of an
     inf-containing column is NaN, `not (NaN < threshold)` is True ->
     kept, absent from the dropped ledger, no warning (probe D1:
     "D1 inf kept by filter: True | ranker score for inf: nan").
     Every downstream estimator in the toolkit REJECTS non-finite
     inputs (evaluate_model's typed guard), so the filter is passing
     garbage it is the right place to catch. The twin (rank_features)
     already reports the undefined case honestly (NaN). NaN variance
     after fillna(0) arises ONLY from inf/-inf cells, so cutting
     NaN-variance columns targets exactly the poison. FIX: cut
     undefined-variance columns, ledger them as NaN (undefined),
     warn naming them; document in the docstring.

[F4] AMBER — interpret.py:545-549, signed_feature_correlations accepts
     complex-dtype columns: pd.api.types.is_numeric_dtype(complex128)
     is True, and the correlation then silently DROPS the imaginary
     part (pandas ComplexWarning, probe B4: "complex column accepted
     silently (unexpected)"). The function's own law is "never invents
     a zero / never fakes" — correlating only the real part of a
     complex column is the same species of silent partial truth.
     FIX: treat complex dtypes as non-numeric (skip + the existing
     naming warning).
