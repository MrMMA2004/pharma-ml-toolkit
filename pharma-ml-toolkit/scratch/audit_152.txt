Evidence (probed, scratch/probe_audit_152.py P1):
* `n_estimators=2.5` passes the `n_estimators < 1` guard (821) and
  dies inside sklearn with a raw InvalidParameterError — outside the
  ModelError convention the docstring promises for the knob (768-770).

  InvalidParameterError from sklearn.

  This half is house-consistent — the sibling guards
  (knn_applicability_domain's `k < 1` / `0.0 < percentile <= 100.0`,
  applicability.py:432-440) behave identically — so it is a
  whole-module convention, not a round defect (recorded as disproven
  below; fix it module-wide or not at all).
Fix sketch: `isinstance(n_estimators, (int, np.integer))` +
`>= 1` in one guard; either validate max_depth (`None or int >= 1`)
or drop it from the documented knob list; leave the string-TYPE cases
to the module-wide convention unless a round takes them all.
